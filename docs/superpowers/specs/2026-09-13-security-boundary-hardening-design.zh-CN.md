# Electron 信任边界与文件/网络安全加固

## 目标

加强 KAMUCL 在渲染进程 IPC 输入、已登记游戏目录、下载产物、压缩包解压和敏感日志方面的安全边界，同时保持现有用户流程，避免无关重构。

## 审计发现

1. `src/main/ipc.ts` 的 `safeDir` 使用字符串前缀判断路径边界。类似 `C:\games2` 的路径可能通过 `startsWith(C:\games)` 检查；已存在的目录链接还可能导致词法路径与实际文件系统目标不一致。
2. 多个文件和导入操作接受渲染进程传入的路径与名称。校验分散在 IPC handler 和核心模块中，容易让同类调用遗漏相同的边界规则。
3. 多个安全敏感流程使用 `adm-zip` 解压归档。解压目标需要统一的条目路径策略，阻止 `../`、绝对路径、带盘符路径以及类似符号链接的归档名称逃出预期目录。
4. 下载重定向需要统一处理协议降级、携带凭据的请求头以及本地/私有目标。认证凭据绝不能跨越来源边界。
5. 更新和启动错误通过宽泛的错误格式化写入日志。在持久化或发送到渲染进程前，日志边界应脱敏常见的凭据格式。

## 设计方案

创建小型、可复用的安全辅助函数，分别负责：

- 基于 `path.relative` 的目录包含关系判断，并对已存在的祖先路径提供可选 `realpath` 检查；
- 安全归档条目规范化和解压目标解析；
- 判断重定向转换并移除来源相关请求头；
- 对 Bearer token、API key、密码和 Cookie 做保守脱敏。

优先在共享核心边界使用这些辅助函数，再收紧当前接受渲染进程路径参数、调用频率最高的 IPC handler。不替换所有现有归档读取器；本次只处理解压和文件写入路径。

## 兼容性

- 现有已登记游戏文件夹继续有效。
- 相对资源路径保持当前支持的格式。
- HTTPS 下载仍可重定向到 HTTPS 镜像，但来源变化时移除来源相关凭据。
- HTTP 仅保留给现有明确支持的本地/测试流程；公开更新和认证路径继续只允许 HTTPS。
- 用户可见错误继续由现有 IPC 错误处理逻辑转换。

## 测试

增加以下针对性测试：

- 兄弟目录前缀绕过以及符号链接/连接点逃逸；
- 归档路径穿越、绝对路径、带盘符路径和合法嵌套条目；
- 同源与跨源重定向时的凭据移除；
- Bearer、查询参数、Cookie 和 API key 的脱敏；
- 现有合法资源导入、下载和更新流程。

先运行针对性测试，再运行 `npx tsc --noEmit`、`npm test` 和 `npm run build`。

## 范围排除

本次不重设计插件系统，不改变认证协议，不新增依赖，不修改发布/版本元数据，也不发布 Release。审计中发现的其他范围漏洞应另开 Issue 或 PR。
